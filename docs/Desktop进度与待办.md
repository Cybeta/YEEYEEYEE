## 2026-10-17 参考图内容指纹

**问题。** 原有引用指纹只含描述、布局、附件路径、子引用和版本标签，不含图片字节。参考图在同一路径被替换后，若路径、大小和修改时间都没变，下游产物不会提示过期，视频前置检查也发现不了。

**改法。** `AssetStore.ContentHashOfFile` 用 `FileStream` + `SHA256` 流式取字节哈希；`ReferenceStaleness` 的新快照（v2）在结构部分之外为每张参考图片记下哈希，网页内嵌 `data:` 图片按解码字节取哈希。比较时 `Matches` 区分新旧格式：v2 记录核对结构 + 字节，旧记录只核对结构。文件缺失或读取失败记为不可读标记，不抛异常；内容相同、仅修改时间不会判成变化。没有引入按路径/大小/修改时间的缓存，也没有全项目后台扫描。

**检测时机。** 哈希只在明确检查点计算：出图批次发起、每张候选提交前复核、视频前置检查、桌面生成链自检。画布节点卡随生成进度高频重画，只比较指纹结构部分（`Of` 默认 `verifyContent: false`），不在渲染路径同步读图。因此同路径换图会在下一次提交/自检时被认定，而不是在卡片重画瞬间显示。

**旧项目兼容。** v2 之前的指纹没有内容基线，不与 v2 直接比字符串；结构没变时保持“未发现变化”，如实承认无法追溯判断历史替换。提交后复核（桌面逐张候选、Web 在途任务）也走同一套兼容比较，不会因为升级到 v2 就把旧任务误判成资产变化。打开项目、加载旧画布不会改写引用或已有产物依据，不清空已采用结果，也不自动生成；重出一次后新产物自然带上 v2 依据。

**验证。** `dotnet build YEEYEEYEE.slnx -c Debug` 成功，0 错误、2 条既有 nullable 警告（`WebChatApi.cs:452`、`Web.Tests/ChatRegression.cs:1230`）；Agent **360 项全部通过**，新增用例覆盖同路径同大小同修改时间换内容、仅改修改时间、文件缺失/读取失败、旧指纹不误报且不被改写。Web 完整回归通过；单独的 `--video-reference-only` 用例仍因既有反射构造参数与 `WebInvocationExecutor` 当前签名不匹配而无法运行（`MissingMethodException`，该测试文件本轮未改动，与本改动无关）；共享指纹逻辑与桌面端是同一份实现。

## 本轮发现与修复

问题都在客户端代码里，`0.1.5.4` 发行包内是旧实现，**必须重新发包才会生效**。

1. **更新包选择没有区分桌面端与 Web 包（潜在误选）。** 原 `UpdateChecker.FindPackage` 只认「第一个 `.zip`」。分端发行后同一个发行版里同时挂着桌面包与 Web 包，两个都是 `.zip`；目前能正常工作只是因为桌面包先上传（见 [发布说明](发布说明.md)），一旦上传顺序变化，桌面端就会把 Web 包装进安装目录——解压结果没有主程序，替换等于把目录搬空。现按文件名词元识别：排除含 `web` 记号的包、优先含 `desktop` 记号的包、只有 Web 包时返回「没有更新包」而不拿它顶替，最后才退回 `.exe`。界面会明确显示「这个发行版只提供 Web 服务包，没有适用的桌面更新包」。
2. **应用内更新会删掉程序旁边的用户数据。** 便携部署的默认项目位置就是程序目录旁的 `Projects`（见 `AppPaths.ProjectsRootCandidates`），替换脚本会把整个程序目录换掉。现在替换脚本在换目录后搬运固定用户数据清单：`Projects`、`sites`、`provider-art`、`ai-config.json`、`ai-key.bin`、`recent-projects.json`。配置文件与密钥通常已在用户配置目录（`%LOCALAPPDATA%\YEEYEEYEE`），程序旁的那一份只是旧版/便携兜底；两类位置都不会被更新删除。
3. **替换失败不再留下半换状态。** 搬运用户数据发生冲突（例如新版目录里已有同名文件/目录）时，脚本把新版目录移到 `.failed-<时间>` 并把旧目录原样恢复；新版本进程启动失败或存活检查未通过时也恢复旧版。旧目录只在新版进程确认存活后才删除。
4. **只有 Web 包不再含糊。** 以前只说「没有 zip 更新包」，用户无法判断是包坏了还是发错端；现在区分「只提供 Web 服务包」与「没有附带桌面包」。

验证方式：Agent **359 项全部通过**（含替换脚本实测、本地测试源下载、包选择、搬运冲突回滚、启动失败回滚）；另用真实 `0.1.5.4 → 0.1.5.5` 包在隔离目录运行替换脚本，确认程序版本变为 `0.1.5.5`，`Projects`/配置/密钥/最近项目/站点/自定义形象全部保留，包内也不含 Web 后端、PDB 或 FFmpeg。

## 0.1.5.4 首次升级与手动迁移

**已发布的 `0.1.5.4` 执行的是它自带的旧更新器，新包无法改变这一次升级过程。** 旧更新器有两个已知风险：

- 只取发行版里的第一个 `.zip`；若上传顺序变化，可能选中 Web 包。
- 替换脚本会删除程序旁的 `Projects`，且搬运失败时仍继续删旧目录。

因此按旧版实际布局区分：

| 旧版本/布局 | 建议 |
| --- | --- |
| `0.1.5.4` 及更早，程序旁存在 `Projects`、`ai-config.json`、`ai-key.bin`、`recent-projects.json`、`provider-art` 或 `sites` 中任意一项 | **必须手动迁移**，不要点「下载并升级」。 |
| `0.1.5.4` 及更早，程序旁没有任何上述用户数据（工程在文档目录、配置在用户配置目录） | 数据丢失风险较低，但旧更新器仍可能误选包。若发行方确认桌面包先上传，可在备份后使用应用内升级；否则同样手动迁移。 |
| 源码包含本批修复的候选版 `0.1.5.5` 及以后 | 支持应用内升级；仍建议先备份程序目录。 |

手动迁移步骤（旧版退出后执行）：

1. 退出旧版程序，确认进程已结束。
2. 把整个旧安装目录复制一份作为恢复副本；不要先删旧目录。
3. 把新 ZIP 解压到**独立的新目录**，不要覆盖旧目录。
4. 在新程序关闭的状态下，把旧目录里的 `Projects`、`ai-config.json`、`ai-key.bin`、`recent-projects.json`、`provider-art`、`sites` 复制到新目录对应位置。若旧版配置已在 `%LOCALAPPDATA%\YEEYEEYEE`，无需重复复制。
5. 启动新目录里的程序，核对版本、最近项目、密钥可用、工程能打开；确认无误后再删除旧目录。
6. 不要同时运行新旧两个实例，避免同一份项目被两边写入。

## 2026-10-17 封面提取与异常媒体边界验收

任务前提里写着「复用现有 FFmpeg」，但**这一版已经没有 FFmpeg**：封面取帧由隐藏的 WebView2（Chromium）页面完成，播放与取帧共用 `LocalVideoPlayer.MediaSession`（带随机令牌的环回 HTTP 服务）把文件喂给 Chromium；媒体探测（`Mp4Concatenator.Probe`）与 MP4 拼接是自带的纯托管实现。所以这次验收针对**实际在跑的那条路**，没有为未使用的 FFmpeg 路径新增任何功能。

- 路径支持范围：本机绝对路径、`.mp4`/`.webm` 等视频扩展名、`asset://` 引用放行；相对路径、UNC/网络、流地址、越界的 `asset://` 引用、音频/图片扩展名、缺失文件一律**当场拒绝并说清原因**（不支持的输入进不到 WebView2）。

- 取帧页面规则：短于 1 秒取中点、其余 0.5 秒；时长读不出来 / 没有可用视频帧 / 解码失败 / 超时四条路都明确结束并带回原因；结束时停掉 `video` 并清掉 `src`。缓存目录：过期与超字节预算的清掉、超过一天的 `.tmp` 清掉、刚写的 `.tmp` 与不认识的文件名不动。
- 容器探针：常规双轨样本量得出轨道/帧/画面；无视频轨时画面如实为 0；空文件、伪装 mp4、头部截断都明确报「读不出来」且不抛异常；量完不留文件占用（源文件可删）。

**本轮结论与修复。** 在上述范围内**没有发现功能性缺陷**（取帧时间、错误结束、句柄与监听释放、缓存清理均按预期）。仅做了一处为可测性的改动：把取帧页面 `Page` 从私有的嵌套宿主 `ThumbnailHost` 移到 `VideoThumbnailService`（纯静态、不依赖宿主状态），并给桌面工程加 `InternalsVisibleTo`，让这些规则能在离线回归里被直接钉住。为验证临时目录里的样本改过一次预期（头部截断到 12 字节会连 `ftyp` 一起截断，报的是「没有 ftyp」而不是「没有 moov」），产品行为本身正确。

**仍未验证：** ① 另一种编码/像素格式（HEVC / VP9 / AV1 / 10-bit 等）——本机无编码器，也造不出真实样本，现有真实媒体全是 H.264；② **真机 WebView2 取帧**（本机无法在锁屏/无人值守下驱动桌面 UI），上面用的是真实 Chromium 跑同一份页面脚本，不等于 WebView2 Runtime 行为；③ 真机界面里「失败后重新选择有效文件并继续」的鼠标级复验。
