## 0.1.3 · 2026-10-05

**这一版没有功能改动**——功能就是 0.1.2 那一份。它做的是两件事：把话说准、把不该留的留干净。
顺带补上 0.1.2 欠的一步：这是**第一个带发布包与 GitHub Release 的版本**（0.1.2 只推了标签）。

### 文档里说准的那几处

- **一处更早的观测与后来的实测对不上，并记了**：那份旁路 bug 的实测里，服务端回 `success`、
  跑了 370 秒、零个文件；后来两份缺必填输入的工作流却是**提交当场 400、并点名缺哪一处**，
  而 `/object_info` 里那一项**确实在 `required` 里、无默认值**。两次都是真实观测，差别可能在
  ComfyUI 版本，没服务器判不了——**都留着**，产品口径按后者。
- **体检写进文档**：`docs/notes-comfyui.md` 新增「导入体检」一节（四类结论与判据、留档 316 份的
  实测数、按下之前那道挡、换机器会怎样），README 的 ComfyUI 接入补了同一件事的提要。
- **构建基线换成 2026-10-05 的全套复跑**（Agent 311 / Core 30 / Migration 8/8 / G6V1 `checks=40` /
  前端 146 项 16 文件 / Web 回归 13 段），并更正一处口径：CS 警告**全量重建是 190 条**，
  早先记的「18 条」是**增量**口径（只重编了改动过的项目）。

### 清掉的无用记录（含纠我自己一处错）

- `待修清单.md` 不再入库：它是探针生成、随那台机器上的文件变化，已进 `.gitignore`（本地那份留着，
  要最新的重新生成一次）。
- **恢复** `provider-art/_generation.json` **入库**：它是「图上画的是哪一版设计」的凭据，
  用例 `ProviderAvatarPromptsMatchTheRecordedBatch` 缺文件就会红——上一版把它当旁产物清出去是错的。
  它仍**不进发布包**（运行时没人读），构建规则只拷那个目录里的图。
- 清掉两条过时本地 ref（DreamForge 时代的残留分支、那次脱敏用的备份标签）。

### 敏感信息

- 探针里写死的真机地址去掉了（默认落回 `127.0.0.1:8188`，打真机自己设 `CHAINPROBE_COMFY`）；
  进仓库的清单里站点只写一个**由地址算出的短标签**（`comfy-a436` 那样）——地址、服务商、账号段都不写。
- 历史清了两层：**未推**的开发历史压成一个提交；**已公开**历史里那处打了码的账号前缀（只在
  `docs/spec-参考图与设定锁定.md` 一个文件里、从 `c3837f1` 起波及 44 份快照）用 `git filter-repo`
  换成 `<站点 id>` 并 force-push 了 `main`（`v0.1.0` / `v0.1.1` 的目标提交没被改到，标签对象按原样保留）。
  **一句实话**：GitHub 不会立刻回收不可达对象，旧 SHA 短期内仍可能取到——要彻底清得让 GitHub
  Support 做一次 GC，或者删库重建。这份说明里也**不再复述那个前缀本身**——写进来就等于又放出去一次。
- 复查一遍：没有跟踪 `.env` / 证书 / 数据库；`appsettings*.json` 只有本机地址；测试与文档里出现的
  密钥都是假值。

### 发布件

`yeeeyee-0.1.3-win-x64.zip`（exe 版本戳 0.1.3.0）。更新链路认的是**最新那版里任意一个 `.zip`**

## 0.1.2 · 2026-10-05

这一版的主线是**把「体检」变成「拦住」，并且把每句话都拿真机校准一遍**。
起因很具体：一份工作流看起来没毛病，提交上去却什么都不出，而界面上说成功了——
用户只会以为「这模型不行」。

### 体检多了两类，也多了「影响到哪几路产物」

- **引用的文件这台机器上没有**（新的一类）：正文结构一点毛病都没有，所以老的几类一个都查不出它来。
  判据是 COMBO 型输入的候选清单**就是服务器当前的文件列表**（`/object_info` 给的），值不在清单里
  就是那个文件没了。把一份装了 316 个工作流的 ComfyUI 全过一遍：**129 处 / 79 份**
  （118 处是示例素材、11 处是模型/依赖）。
- 每条结论现在还带一句**「有几路产物靠它」**：0 就是没人读、掉什么都无所谓。
  同一处毛病落在没人读的节点上，说成「出不了片」就是吓人（实测 T12：ComfyUI 自己点名了 4 处缺模型，
  可那 4 处服务的产物自己过不了校验，同一份里别的产物照样出）。

### 出片前先拦住，不再等 ComfyUI 回错误

绑定时「给不满就只写前几个，多出来的入口保持它原来的示例图」是有意的（不拿同一张图去凑数），
可那些示例来自别人的机器。实测 B02（单双三图）：用户给一张、另外两个入口留着自己的 `33.jpg`，
而那张图在服务器上早没了——提交回 `400 custom_validation_failed`（点名 `Invalid image file: 33.jpg`），
连队列都进不去。现在按下之前就说清差哪个入口：

> 出图 B02 → 0.2 秒失败：图槽位（节点 262.image）还留着它的示例 `33.jpg`，
> 而那份文件已经不在服务器上了，有 6 路产物靠它……

留档那 316 份实测：**给 1 张图时有 48 份会被这道挡拦住**——这些以前都是一次白交的 400。

### 真机把几句话说准了（被推翻的都改了）

| 情形 | 提交 | 跑起来 |
|---|---|---|
| 缺必填输入（断线、我们丢的） | **400** `prompt_outputs_failed_validation`（点名缺哪一处） | 一条都不跑 |
| 缺素材（`LoadImage` 这类），且**有产物依赖它** | **400** `custom_validation_failed`（点名文件名） | 连队列都进不去 |
| 缺模型（`UNETLoader` 这类只做清单校验） | **200** + `node_errors` 里 `value_not_in_list` | 靠它的那几路拿不到结果，别的产物照样出 |
| 文件没了、但**没有任何产物靠它** | **200**（`node_errors` 甚至是空的） | 不影响出片 |

所以「会不会当场被挡下」**不看文件类型，看有没有产物依赖它**。产品里那句「服务端往往还回 success、
只是产出为空」和后来那句「提交照样会被拒收」都说过头了，一并改成上表的口径。

### 离线也能复现：假 ComfyUI 与探针进了仓库

- `tools/chainprobe`：导入链与出片链都能在**没有真服务器**的情况下跑完
  （`demolocal` / `demogen` 打的是本地假 ComfyUI，数据取自真机留档）。
- 顺带能导一张**待修清单**（`repair`）：要补的文件（去重）、要接的线（逐条「节点.输入」）、
  失效的示例素材（没人读的标明可以先不管）。当前那台机器上是 11 / 99 / 118 处。

### 修掉的问题

- **点「让大模型认一认」会让应用崩溃**：库的回调在 `ConfigureAwait(false)` 之后跨线程写界面
  （`Call from invalid thread`）。Console 测试跨线程安全，所以永远抓不到——这一类全扫了一遍。
- **「文件清单式」底图入口整类漏掉**：`MultiImageLoader.image_paths` 是多行文本，既不是 `LoadImage`
  家族、也不是候选清单形态，导致「这份工作流能收首帧」报成 False。
- **换一台服务器会静默失效的一处**：固定的候选项在新写法里是对象（真值在 `key` 上），
  以前整条跳过、一声不吭——那会让「一处缺文件都没报」被读成「文件都在」。现在读得懂就读，
  真读不懂的如实报「这几处我查不了」。
- **不再把「不是我们的错」说成我们的错**：链子尽头那个节点的类型这台服务器上根本没有时
  （自定义节点没装、或它本来就是纯前端件），说明白是哪一类、链子是从那儿断的。

### 敏感信息

- 探针里写死的真机地址去掉了（默认落回本机 `127.0.0.1:8188`，打真机自己设 `CHAINPROBE_COMFY`）；
  进仓库的清单里站点只写一个**由地址算出的短标签**（`comfy-a436` 那样）——地址、服务商、账号段都不写。
- 历史里清了两层：先把这一版之前**未推**的开发历史压成一个提交；随后又用 `git filter-repo`
  把**已公开**历史里那处打了码的账号前缀（只在 `docs/spec-参考图与设定锁定.md` 一个文件里、
  从 `c3837f1` 起波及 44 份快照）换成 `<站点 id>`，并 force-push 了 `main`
  （`v0.1.0` / `v0.1.1` 的目标提交没被改到，标签对象按原样保留）。
  **一句实话**：GitHub 不会立刻回收不可达对象，旧 SHA 短期内仍可能取到——要彻底清得让
  GitHub Support 做一次 GC，或者删库重建。这份说明里也**不再复述那个前缀本身**——
  写进来就等于又放出去一次。
- 厂家形象那份生成记录（`provider-art/_generation.json`）**留在仓库里**：它是「图上画的是哪一版
  设计」的凭据，有用例逐条对账（`ProviderAvatarPromptsMatchTheRecordedBatch` 缺文件就会红）。
  只是它**不进发布包**——运行时没人读它，构建规则因此只拷那个目录里的图。
- 复查了一遍：没有跟踪 `.env` / 证书 / 数据库；`appsettings*.json` 只有本机地址；
  测试与文档里出现的密钥都是假值。

### 还没做（下一版的候选）

1. **认不认「直通节点」的写死表**：换台装了别的 Set/Get、别的 bypasser 的服务器，
   仍然可能把「原稿本来没问题」误报成「我们丢了输入」。
2. **媒体入口靠「类名 + 输入名」匹配**：认不出入口时该说「我没认出来，请指给我」，而不是断言「用不了」。
3. **内置兜底模板**写死了 `KSampler` / `euler` / 512×512：提交前该拿 `object_info` 核一遍。
4. 还有几处随机器变的假设（工作流按中文文件夹名分类、端点写死、尺寸对齐 16、帧数模数），
   都在 `TODO.local.md` 第 206 轮里逐条记着与最小兜底方案。
