## 0.1.5.8 已发布（2026-11-02）

状态：**已发布**。源码版本为 `0.1.5.8`（版本号来源仍是桌面工程 `<Version>`，Web 包跟随同一版本号），tag `v0.1.5.8`。桌面与 Web 两个 ZIP 已上传到 [GitHub Release v0.1.5.8](https://github.com/Cybeta/YEEYEEYEE/releases/tag/v0.1.5.8)。本版把「大画布打开卡死、空闲动画吃 CPU」从根上修掉，并带上只在本地打包过、从未上传的 `0.1.5.7` 内容（技能可见与运行、项目级技能补充、Web 聊天重问）。

### 面向用户的更新

**卡死与内存**

- 引用指纹里内嵌的 `data:` 图片不再整段 base64 复制，改为内容哈希短写法（`data-url#<sha256>`）；同一份字节仍判为一致，换图仍会报「设定已更新」。旧画布打开时自动换算，历史记录与当前计算可以互相比较。
- 画布与实体库改为文件流反序列化；画布列表只读文件头 8 KB，不再为了列出标题而把整份画布读进内存。
- 深拷贝改走 UTF-8 字节并放宽转义，避开默认编码器为长 base64 预留整块缓冲。
- Web 端上传的参考图/视频落到素材目录，实体里只记 `asset://` 引用；库保存失败时删除刚写入的文件，不留孤儿。
- 结果：示例项目打开的内存峰值从 5.3 GB 降到约 320 MB（稳定约 299 MB），其中单个画布文件从 334 MB 降到 73 KB。

**空闲功耗**

- 启动页去掉常驻动画；画布环境动画降到 20 fps 并改用 `RenderTransform`，窗口不可见、最小化或失焦时暂停。
- 结果：启动页空闲 CPU 约 34% → 约 2%，项目内空闲约 30% → 约 15.5%，最小化后约 4%（本机实测，口径见 Desktop 进度文档）。

**技能（`0.1.5.7` 内容）**

- 上下文列出本机可运行的接口池与 ComfyUI 工作流，用合成 id 精确反查；无推荐项时每种用途列前 3 份。
- 新增 suggest 邀请卡与 run_skill 确认卡：花钱仍需用户点击，自动模式不代扣，视频不直达。
- 新增 patch_skill 项目级技能补充：只追加、版本递增、旧措辞留档，设置页可查看历史。
- Web 聊天：协议缺失或该结构化却只回正文时自动重问一次；ask 选项点击即发送并置灰。

### 0.1.5.4 及更早版本首次升级

**已发布的 `0.1.5.4` 执行的是它自带的旧更新器，新包无法改变这一次升级过程。** 旧更新器只取发行版里第一个 `.zip`，且替换脚本会删除程序旁的 `Projects`，搬运失败时仍可能继续删除旧目录。

程序旁存在 `Projects`、`ai-config.json`、`ai-key.bin`、`recent-projects.json`、`provider-art` 或 `sites` 中任意一项的便携安装，**必须手动迁移**：

1. 退出旧版并确认进程结束。
2. 复制整个旧安装目录作为恢复副本，不要先删除。
3. 把新 ZIP 解压到独立的新目录，不覆盖旧目录。
4. 在新程序关闭时，把旧目录中的上述用户数据复制到新目录对应位置；配置已在 `%LOCALAPPDATA%\YEEYEEYEE` 的无需重复复制。
5. 启动新目录程序，核对版本、最近项目、密钥和工程可打开，确认后再删除旧目录。
6. 不要同时运行新旧两个实例。

完整表格与边界见 [Desktop 进度与待办](Desktop进度与待办.md#0154-首次升级与手动迁移)。

### Web 端

- 独立数据目录：程序位于 `versions\<版本>`，持久数据固定放在 `data\`；升级只替换程序目录，不改写 `data\`。
- 安装与迁移：`install-web.ps1` 建立版本目录与固定数据目录，把旧布局的账号、任务、聊天、附件、素材、配置、密钥和项目复制并逐文件校验，保留旧目录作为恢复副本。

- 回滚：`rollback-web.ps1` 区分程序回滚与数据恢复。程序回滚默认保留当前数据；数据恢复必须显式 `-RestoreData` 与 `-ConfirmDataLoss`，并先把当前数据移到 `backups\data-before-rollback-<时间>`。
